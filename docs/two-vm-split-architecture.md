# Two-VM Split Architecture for Credential Isolation

**Project:** APPENG
**Type:** Feature
**Epic:** Secure Agent Workspace Validated Pattern
**Priority:** High
**Component:** RH_AI_Blueprints
**Labels:** secure_agent_workspace, openshell, credential_isolation, two_vm
**Branch:** `feat/rh-two-vm-split-arch`

## Summary

Split the single-VM deployment into two VMs to isolate AI agent execution from real provider credentials. The agent VM runs OpenClaw with placeholder credentials. The integrations VM runs scoped proxy services with real API tokens. The agent never sees real credentials.

## Architecture

```
┌─────────────────────────────────┐         ┌───────────────────────────────┐
│          Agent VM               │         │     Integrations VM           │
│  (openshell-saw)                │         │  (openshell-saw-integ)        │
│                                 │         │                               │
│  ┌───────────────────────┐      │         │  ┌─────────────────────────┐  │
│  │ OpenClaw sandbox      │      │ bearer  │  │ Inference proxy (py)    │  │
│  │ - placeholder creds   │──────┼────────>│  │ :18083 (systemd)        │  │
│  │ - inference-proxy     │      │         │  │ validates bearer,       │  │
│  │   provider attached   │      │         │  │ swaps for real API key  │  │
│  └───────────────────────┘      │         │  └─────────────────────────┘  │
│                                 │         │                               │
│  Gateway (mTLS + OIDC)          │ bearer  │  ┌─────────────────────────┐  │
│  :17670 (gRPC)                  │────────>│  │ gmail-read proxy        │  │
│                                 │         │  │ :18080 (sandbox)        │  │
│  Route (passthrough TLS)        │         │  │ BOM-driven, auto-start  │  │
│  *.apps.cluster/                │         │  └─────────────────────────┘  │
│                                 │         │                               │
│  Dashboard + Web UI             │         │  Gateway (mTLS only)          │
│                                 │         │  No route (internal only)     │
└─────────────────────────────────┘         └───────────────────────────────┘
        │                                            │
        │        K8s Service + NetworkPolicy          │
        │  openshell-saw-integ-gateway:18080-18083   │
        └────────────────────────────────────────────┘
```

### Agent VM
- Runs OpenClaw sandbox (the AI agent)
- Providers configured with placeholder credentials
- `inference-proxy` provider routes inference through integ VM
- Dashboard + OIDC gateway for user-facing access
- No real API tokens present

### Integrations VM
- Runs proxy sandboxes (no AI agent) — driven by BOM profiles
- Inference reverse proxy as a systemd service (port 18083)
- Additional proxy sandboxes (gmail-read, slack, etc.) via `apply_bom.py`
- Real credentials stored on the VM, never exposed to agent
- Internal-only (no OpenShift Route)

### Inter-VM Communication
- Agent sandbox → integ VM via K8s Service
- Bearer token auth: agent presents token, integ proxy validates SHA256
- Bearer generated by integ VM setup Job, stored in K8s Secret `inter-vm-bearer`
- Agent VM setup Job reads bearer from Secret, stores on agent VM

### Authentication
- **During setup**: mTLS only (OIDC not yet enabled)
- **After setup**: `patch-oidc.sh` enables dual auth:
  - `OPENSHELL_ENABLE_MTLS_AUTH=true` keeps mTLS working for admin ops
  - `OPENSHELL_OIDC_ISSUER` enables OIDC for external user access
  - Gateway accepts either method independently (first-match-wins in auth chain)

## Implementation

### Deployment Flow

Two deployment paths supported:

**New VMs (OpenShift Virtualization):**
```
make generate-keys
make deploy-config API_KEY=...       # SSH secrets + BOM + inference secret
make deploy-integ-vm                 # helm upgrade --install
make deploy-agent-vm                 # helm upgrade --install
```

**Pre-existing VMs:**
```
make deploy-config API_KEY=...
make deploy-integ-vm INTEG_HOST=10.0.1.6
make deploy-agent-vm AGENT_HOST=10.0.1.5 INTEG_HOST=10.0.1.6
```

### Chart Structure (`charts/openshell-saw/`)

Same chart for both VMs, differentiated by `role: agent|integrations|standalone`:

- `values.yaml`: `role` controls which setup phases run
- `overrides/openshell-saw.yaml`: agent VM config
- `overrides/openshell-saw-integ.yaml`: integrations VM config
- `templates/`: VM, Service, Job, CloudInit, Route, NetworkPolicy

### Setup Scripts (`charts/openshell-saw/files/`)

| Script | Phase | Role |
|--------|-------|------|
| `install-deps.sh` | 1 | all |
| `bootstrap-golden-image.sh` | 2 | all |
| `wait-for-vm.sh` | 3 | all |
| `upgrade-openshell.sh` | 4 | all — upgrades binaries, waits for gateway health |
| `setup-agent-providers.sh` | 5 | agent — waits for bearer, creates inference-proxy provider |
| `check-governance.sh` | 6 | all |
| `setup-integ-proxies.sh` | 7 | integrations — BOM-driven proxy setup + inference proxy |
| `setup-bom-profiles.sh` | 7 | agent/standalone — BOM-driven sandbox setup |
| `setup-keycloak-redirect.sh` | 8 | agent/standalone (if dashboard enabled) |
| `patch-oidc.sh` | 9 | all — enables OIDC + mTLS dual auth |

### BOM Profiles (`charts/saw-bom/`)

Profiles follow the `<profile>/<workspace>/` directory convention:

```
profiles/
  data-science/          # agent VM
    default/
      workspace.yaml
      providers.yaml
      sandbox.yaml
  integrations/          # integ VM
    default/
      workspace.yaml
      sandbox.yaml       # supports command + exposePort fields
```

`apply_bom.py` handles both Docker and Podman, and after creating a sandbox:
- Starts the process specified by `command`
- Exposes the port specified by `exposePort` via `openshell service expose`

### Key Variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `AGENT_VM_NAME` | `openshell-saw` | Agent VM Helm release name |
| `INTEG_VM_NAME` | `openshell-saw-integ` | Integ VM Helm release name |
| `AGENT_HOST` | (empty) | Pre-existing agent VM IP |
| `INTEG_HOST` | (empty) | Pre-existing integ VM IP |
| `INTEG_PORT` | `18083` | Inference proxy port |
| `KEYCLOAK_NS` | `$(NS)` | Namespace where Keycloak is installed |

## Constraints

- OpenClaw agent only (NemoClaw requires Docker for onboarding)
- Same golden image for both VMs
- OpenShell has no native gateway-to-gateway federation
- `openshell inference set` only supports built-in provider types — custom providers use direct baseUrl routing
- Sandbox network policy must whitelist the integ VM endpoint for direct access

## Testing
