# Two-VM Split Architecture for Credential Isolation

**Project:** APPENG
**Type:** Feature
**Epic:** Secure Agent Workspace Validated Pattern
**Priority:** High
**Component:** RH_AI_Blueprints
**Labels:** secure_agent_workspace, openshell, credential_isolation, two_vm
**Branch:** `feat/rh-two-vm-split-arch`

## Summary

Split the single-VM deployment into two VMs per user to isolate AI agent execution from real provider credentials. The agent VM runs the AI agent (OpenClaw) with dummy/proxy credentials. The integrations VM runs scoped credential proxy sandboxes with real API tokens. The agent never sees real credentials.

## Architecture

### Agent VM
- Runs OpenClaw sandbox (the AI agent)
- Providers configured with proxy/dummy credentials
- OpenShell supervisor restricts outbound to integrations VM only
- Dashboard + OAuth2 proxy for user-facing web UI
- No real API tokens present

### Integrations VM
- Runs generic proxy sandboxes (no AI agent)
- Each sandbox is a scoped proxy: web-search, inference-proxy, etc.
- Real credentials configured on providers here
- Accepts connections from Agent VM via mTLS
- Per-workload credential management

### Inter-VM Communication
- Agent VM sandbox -> Agent VM gateway (via podman bridge 10.88.0.1)
- Agent VM -> Integrations VM via K8s Service (mTLS, shared CA)
- Shared CA generated by setup Job, stored in K8s Secret
- Governance interceptor enforces L7 policies on both VMs

## Implementation

### Chart changes (`charts/openshell-saw/`)
- `values.yaml`: `integrationsVm.enabled: false` (gated)
- `templates/virtualmachine-integ.yaml`: second VM (2 cores, 4Gi, gateway+ssh ports)
- `templates/service-integ.yaml`: ClusterIP for integrations VM
- `templates/cloudinit-integ.yaml`: mTLS enabled, no OIDC
- `files/run-setup.sh`: parameterized `guest_ssh_to`/`guest_scp_to`, new phases
- `files/setup-shared-tls.sh`: shared CA generation + cert distribution
- `files/setup-integ-vm.sh`: applies BOM profiles to integrations VM

### BOM changes (`charts/saw-bom/`)
- `profiles/integrations/default/`: workspace, providers, generic proxy sandboxes
- `values.yaml`: `integrationsProfiles` list (empty by default)
- `templates/configmap-bom.yaml`: second ConfigMap `saw-bom-integ-profiles`

### Governance (`charts/governance-policy/`)
- `profiles/integrations-proxy.yaml`: restricts Agent VM outbound to integrations VM

## Constraints

- Podman runtime only (NemoClaw requires Docker, not supported in this branch)
- OpenClaw agent only, default workspace
- Same golden image (openshell-gateway podman variant) for both VMs
- OpenShell has no native gateway-to-gateway federation
- All gated behind `integrationsVm.enabled` — single-VM mode unchanged

## Testing

1. `helm template` with `integrationsVm.enabled=true` — both VMs render
2. Deploy — both VMs reach Running, SSH accessible
3. Setup Job configures both VMs with shared TLS
4. Integrations VM: `openshell sandbox list` shows proxy sandboxes
5. Agent VM: provider pointing to integrations VM service
6. E2E: agent request -> agent gateway -> integ gateway -> proxy sandbox -> external API
7. Security: agent cannot reach external APIs directly
