# Red Hat One Lab Submission: Secure Agent Workspace

## Title

"Secure Agent Workspace: Deploy governed AI agents on Red Hat OpenShift in 60 minutes"

Title options (≤100 chars, sentence case except product/proper names):

1. "Secure Agent Workspace: a hands-on Red Hat OpenShift quickstart for governed AI agents"
2. "Unblocking AI agents: a hands-on Red Hat OpenShift quickstart for security-conscious teams"
3. "Prove it's safe: a hands-on Red Hat OpenShift lab for governed AI agents"

---

## Revised outline (120 min)

1. **The problem, shown first (10 min)** — Facilitators open with a live Secure Agent Workspace already running: a user logs in with their own identity and works with an AI agent (OpenClaw) inside an isolated, per-user environment. Frame the sales moment: "how many of your accounts have said no to AI agents because security can't see or control what they touch?"

2. **Where this fits (5 min)** — Position Secure Agent Workspace as the flagship entry point into the maintained Red Hat OpenShift AI quickstart catalog.

3. **Guided build (60 min)** — Attendees log in via single sign-on, provision their own sandbox with the same maintained quickstart, and start a conversation with the agent running inside it. (Facilitators pre-provision the underlying cluster, operators, identity, and secrets management before the session — attendees only need a laptop and network access.)

4. **Prove it (20 min)** — The centerpiece: attendees try to access a neighbor's sandbox to see isolation hold, check the audit trail to see exactly what the agent touched, and swap the underlying model to show the pattern isn't locked to one provider.

5. **Pitch practice (15 min)** — Paired exercise: each SA delivers a talk track to a partner playing a skeptical security/compliance stakeholder, reframing "AI agents are a risk" into "here's how we govern them."

6. **Wrap-up & catalog map (10 min)** — Where to find the rest of the catalog and how it stays current.

## Outcomes

1. Provision and use a per-user Secure Agent Workspace sandbox running an AI agent on Red Hat OpenShift, from single sign-on to a live conversation.
2. Demonstrate the isolation, identity, and secrets-management controls that let a security team say yes to AI agents.
3. Show an audit trail proving what an agent did and didn't touch, and swap inference providers without re-architecting the sandbox.
4. Deliver a confident talk track that reframes an AI-agent security objection into a governance story.
5. Locate the right quickstart for other AI conversations from the maintained catalog.
